# PhoneSimulator 旧版 Excel 配置工具

这个目录保留 PhoneSimulator 的旧版兼容工作流：用 Excel 管理手机初始内容和剧情，再由 Python 转换成网页可以读取的 JSON。新作品推荐使用 [`config-editor/`](../config-editor/README.md) 可视化编辑器；已有 Excel 作品可以继续使用本工具，也可以一次性导入可视化编辑器后迁移。

同一个作品不要同时维护 Excel 与 `.phone-project.json`。两种入口都会覆盖 `phone-simulator/src/data/content.json` 和 `story.json`，不会自动合并或双向同步。

整个项目的安装、GitHub Desktop 备份和 Cloudflare Pages 发布步骤见[仓库总说明](../README.md)。Vue 前端功能和运行时结构见[前端说明](../phone-simulator/README.md)。

新对话开始处理 Excel 或字段任务时，先确认三件事：

1. `outputs/phone-config-template.xlsx` 是旧版流程唯一维护的兼容工作簿。对外模板保留表头、系统字段、下拉选项、必要结构行和填写说明，作品专属文案由使用者自行填写；`content.json` 和 `story.json` 是转换结果。
2. Excel 与 JSON 不一致不一定是错误；作者可能正在编辑工作簿但尚未准备发布。运行转换器前先确认用户意图。
3. 新增或改名字段不是只改 Excel：还要同步 `convert.py`、运行时 JSON 结构、Vue 读取代码、表内说明与相关 README。

## 目录内容

```text
excel-json-tool/
├─ outputs/phone-config-template.xlsx  完整配置表与示例
├─ convert.py                          Excel 转 JSON 脚本
├─ requirements.txt                    Python 依赖
└─ README.md                           本说明
```

继续使用旧版流程时，`phone-config-template.xlsx` 是该流程的可读配置源，建议保留这个固定文件名并直接修改。转换结果写入：

```text
../phone-simulator/src/data/content.json
../phone-simulator/src/data/story.json
```

转换器使用脚本自身所在目录推导路径，所以整个 `PhoneSimulator` 文件夹移动或重命名后仍能工作；但 `excel-json-tool/` 和 `phone-simulator/` 必须继续保持同级。

不要在 `outputs/` 中长期维护第二份手工复制的兼容工作簿。临时测试文件应输出到明确的临时目录，并避免覆盖作者正在编辑的文件。

## 继续使用旧版 Excel

需要 Python 3.10 或更高版本。在本目录运行：

```powershell
python -m pip install -r requirements.txt
```

安装只需完成一次。之后每次使用旧流程修改内容时：

1. 打开 `outputs/phone-config-template.xlsx`。
2. 按表头和顶部说明修改，保存后关闭 Excel。
3. 在本目录运行：

```powershell
python convert.py
```

4. 看到转换成功提示后，进入 `../phone-simulator/` 运行：

```powershell
npm run build
```

转换器报错时不会把错误配置当作成功结果写入。按照终端指出的工作表、行号或字段修正后重新运行即可。

## 迁移到可视化编辑器

决定迁移现有作品时，在 `config-editor/` 运行 `npm run dev`，点击顶部“导入 Excel”并选择当前工作簿。检查导入摘要后立即保存为 `.phone-project.json`；以后打开该项目文件继续编辑，并通过“导出 JSON”更新手机网页数据。

这是一次性迁移，不是同步功能。迁移后可以保留原工作簿作为历史备份，但不要再用它覆盖可视化项目导出的 JSON。

## 工作表说明

工作簿包含一张总说明、微信以外的原有初始内容与剧情表，以及 13 张微信相关配置表。

| 类型 | 工作表 |
| --- | --- |
| 使用说明 | 填写说明 |
| 初始内容 | 基础设置、桌面应用、相册、备忘录、闹钟、联系人、短信记录、通话记录、音乐、浏览记录、锁屏通知、邮件、日历、地图地点、小红书搜索记录 |
| 剧情内容 | 短信剧情、电话剧情、电话剧情内容、剧情事件、剧情分支、主动通话规则、主动通话条件 |
| 微信内容 | 微信账号、微信联系人、微信群聊、微信群成员、微信会话、微信消息、朋友圈、朋友圈点赞、朋友圈评论 |
| 微信剧情 | 微信剧情、朋友圈发布剧情、朋友圈玩家评论剧情、朋友圈互动剧情；均在“剧情事件”中引用 |

表格阅读规则：

- 中文表头供内容作者阅读；同一格第二行的小号英文是对应 JSON 字段名，便于排错，请不要修改。
- 列名含“（可空）”时可以不填。
- 带下拉箭头的字段必须从选项中选择，不要手写近似文字。
- ID 用来跨表关联，必须保持唯一、稳定，并避免空格和临时中文描述。
- 数据行的显示顺序或序号决定同类内容的排列与执行顺序。
- 表格顶部的说明优先于通用说明，特别是素材路径和占位素材的优先级。
- 非“填写说明”工作表的表头必须同时保留中文字段名和同格第二行的 JSON 字段名；修改 schema 时不要只改其中一行。

例如，短信记录和短信剧情中的“联系人 ID”必须能在“联系人”表找到；剧情事件引用的短信剧情 ID、电话对白 ID、后续事件 ID 也必须存在。转换器会检查常见的重复 ID 和缺失关联。

## 从空模板开始填写

对外模板即使清除了作品文案，也应保留所有工作表、表头、英文系统字段、数据验证和必要的结构行。建议按以下顺序填写，避免先写剧情、后补关联对象造成大量转换错误：

1. **基础设置**：先填写网页名称、四位密码、手机尺寸与圆角、电量参数、用户名、Wi-Fi、主题色、壁纸和天气。不要删除“系统字段（不要修改）”列中的字段路径；只修改“填写值”。
2. **桌面应用**：保留已有 App ID、组件名和顺序。用“是否使用”控制入口是否显示，按需替换显示名称和图标路径，不要把暂时不用的 App 组件名改成其他文字。
3. **基础对象**：先建立联系人、微信账号、微信联系人、微信群聊、微信会话和地图地点，再填写引用这些对象的短信、通话、微信消息和定位消息。
4. **初始内容**：填写相册、备忘录、闹钟、通话记录、音乐、锁屏通知、邮件、日历、朋友圈等打开网页时已经存在的内容。不使用的内容表可以只保留表头，不要删除工作表。
5. **剧情脚本**：先写短信剧情、微信剧情、电话对白、朋友圈发布/评论/互动脚本。一个脚本可以占多行；同一脚本 ID 下用序号确定句子或动作顺序。
6. **剧情事件与分支**：最后把脚本挂到事件上，设置初始事件、计时或操作触发、发生内容和结果分支。先完成一条能从初始事件走到结束的主线，再增加来电结果、重试和支线。
7. **转换与编译**：关闭 Excel 后运行 `python convert.py`，根据工作表名和行号修正错误；转换成功后再运行 `npm run build`。

### 必须保留的结构

- “填写说明”可以补充说明，但不要改动其他表第二行英文系统字段。
- “基础设置”中的系统字段行和“桌面应用”中的 App ID、组件名属于程序结构，不应因清空示例文案而删除。
- “微信账号”必须且只能有一行，至少填写昵称和微信号；玩家在微信相关表中的固定 ID 是 `SELF`。
- 每个数据表可以没有内容行，但只要填写了一行，该行的必填 ID 和关联字段就必须完整。
- 不要通过复制整个工作簿制作多个长期版本。需要试验时使用 `--input` 和 `--out-dir` 指向临时文件或目录。

### ID 与跨表关联

ID 是内部引用，不是界面文案。建议使用简短、稳定、无空格的英文与数字组合，例如 `contact-lin`、`sms-opening`、`dialogue-call-1`、`event-start`。显示名称以后可以修改，ID 一旦被其他表引用就不要随意更换。

| 填写位置 | 必须先存在于 |
| --- | --- |
| 短信记录、短信剧情、电话剧情、通话记录中的联系人 ID | `联系人` |
| 微信单聊目标、微信消息或微信剧情发送人 | `微信联系人`；玩家自己使用 `SELF` |
| 微信群成员中的群聊 ID | `微信群聊` |
| 微信消息、微信剧情中的会话 ID | `微信会话` |
| 定位消息中的地图地点 ID | `地图地点` |
| 朋友圈点赞、评论、互动中的朋友圈 ID | `朋友圈`或`朋友圈发布剧情`将要生成的朋友圈 ID |
| 剧情事件引用的脚本或对白 ID | 对应的短信、微信、朋友圈剧情表或`电话剧情` |
| 剧情分支、主动通话条件中的事件 ID | `剧情事件` |
| 评论回复对象 ID | 初始评论、玩家评论剧情或互动剧情将要生成的评论 ID |

同一张表中的主 ID 必须唯一。一个脚本分成多行时可以重复脚本 ID，但同一脚本内的消息序号、对白序号、互动序号不能重复。群成员、点赞等组合关系也不能重复。

### 空白、零值与多行内容

- 列名带“（可空）”才可以留空。不要用空格、`-`、`无`或`null`代替空白单元格。
- 空白和数字 `0` 含义不同。例如拨打次数上限为 `0` 表示不设上限，等待秒数为 `0` 表示立即执行；可空字段留空表示不配置。
- “是/否”、消息类型、方向、事件状态等枚举优先使用单元格下拉，不要手写近义词。
- 多个朋友圈图片路径、重试结果等列表使用 `Alt + Enter` 在同一单元格内换行，一行一项。普通长文案可以保留自然换行，但不要用逗号代替本应逐行填写的列表。
- 序号只负责同组内容的执行或显示顺序，不等同于 ID。建议使用递增整数，并在同一脚本或会话内保持唯一。

### 对外整理检查

如果要发布一个不含作品文案的模板，清空 Excel 只是其中一步：

1. 保留表头、系统字段、下拉验证、填写说明和必要结构行，删除作品专属对白、联系人资料和剧情内容。
2. 检查 `phone-simulator/src/data/content.json` 与 `story.json`。它们是已经生成的运行时内容，不会因为 Excel 被清空而自动清空。
3. 检查 `phone-simulator/public/media/`，删除不应随模板分发的照片、头像、音乐和地图素材，并同步清理对应路径。
4. 若要让网页运行空白模板内容，使用整理后的兼容工作簿重新运行转换器，再执行生产构建验证。
5. 不要提交 `dist/`、`node_modules/`、Excel 临时文件或另存的工作副本。

## 常用填写格式

### 四位锁屏密码

密码必须恰好是四位数字，例如：

```text
2799
0123
```

不能包含空格、字母或符号。若 Excel 把 `0123` 自动识别为数字 `123`，转换器会按四位密码补回开头的 `0`；超过四位或含非数字字符会报错。

### 日期、时间和秒数

- 日期：`YYYY-MM-DD`，例如 `2026-10-24`。
- `基础设置`中的“固定日期（可空）”也使用 `YYYY-MM-DD`。填写后，锁屏、桌面、日历和天气始终使用该日期；留空时使用玩家本地日期。它不会改变状态栏、闹钟、消息或剧情使用的本地时间。
- `基础设置`中的“初始手机电量（%）”填写 1～100 的整数；“每格电量耗时（秒）”控制电量每降低 1% 的间隔。
- 只要还有本次实际进入的主线或支线未完成，电量最低保持在 1%；全部完成后按“剧情完成后关机等待（秒）”延迟关机，示例值为 30 秒。
- 固定时间：`HH:MM`，例如 `07:30`。
- 剧情延迟、等待、超时和振铃时长：统一按秒填写，可以使用 `1.2` 这类小数。
- 动态显示玩家打开网页时的本地时间：严格填写 `LOCAL_TIME`。

`LOCAL_TIME` 可用于相册显示日期、备忘录更新时间、联系人列表时间、短信和通话记录时间、浏览记录、锁屏通知、邮件和日历显示时间。普通文字（包括“刚刚”）会原样显示；留空则不显示。

Excel 自动把日期、时间或纯数字识别为其他单元格类型通常不会影响转换，脚本会根据该列规定的格式解析，而不是依赖单元格显示类型。

### 素材路径

素材放在 `../phone-simulator/public/media/`，Excel 中填写：

```text
/media/img1.jpg
/media/song.mp3
```

必须包含文件后缀，文件名大小写和扩展名应与实际文件一致。路径素材优先；路径留空时才使用同一行配置的占位渐变、默认头像、主题色或默认铃声。

HEIC 需要先真正转换为 JPEG、PNG 或 WebP，不能只改扩展名。大体积图片和音频会显著增加网页加载时间，发布前建议压缩。

## 初始内容的关键规则

- `基础设置`的“网页名称”只控制浏览器标签页标题，不会显示在手机界面中；修改后需要重新运行转换器并构建网页。
- `基础设置`的“固定日期（可空）”用于锁屏日期、桌面日期、日历图标、日历 App 和天气生成；只覆盖年月日，所有小时、分钟、秒和计时器仍使用玩家本地时间。
- `桌面应用`的“是否使用”控制桌面入口；组件名是代码注册值，不要随意修改。该表不配置未读角标：信息从联系人未读数汇总，邮件从邮件未读状态汇总，微信从“微信消息”的未读状态汇总。图标路径用于桌面、底部栏和通知；日历与时钟留空，日历按固定日期（未配置时为本地日期）绘制，时钟按本地时间实时绘制。其他图标路径为空或加载失败时使用代码内置图标。计算器组件名为 `CalculatorApp`，不需要单独的内容表。
- `相册`不配置图片标题；路径失败时显示占位素材。
- `备忘录`的“是否置顶”留空时按“否”处理。所有置顶项显示在列表前面，并保持表内行顺序；非置顶项按更新时间从晚到早排列。建议使用 `YYYY-MM-DD HH:MM`、`YYYY-MM-DD`、`HH:MM` 或 `LOCAL_TIME`，无法识别或留空的时间会排在其他非置顶项之后，并保持表内顺序。
- `联系人`保存姓名与头像；短信列表预览由程序自动取最后一条消息，并限制为一行。
- `地图地点`的 SVG 路径必须填写 `/media/...svg`。“是否初始收藏”为“是”时必须填保存日期；为“否”时该列留空。初始最近与收藏可以同时为“是”。
- 地图类型可选：住宅、工作地点、餐饮、咖啡、商店、酒店、交通、医院、学校、公园、景点、舞蹈室、录音室和其他。前端按类型选择固定底色和 Lucide 图标。
- 小红书首页长图在`基础设置`填写 `/media/...` 路径；`小红书搜索记录`配置显示顺序、搜索内容和可选跳转链接。链接留空时点击无反应，填写时必须使用 `http://` 或 `https://`，前端会在新标签页打开以保留模拟器原页和滚动进度。
- `通话记录`只通过联系人 ID 读取姓名和头像，所有记录都可以点击回拨。
- `音乐`填写 MP3 后，网页优先使用音频元数据中的真实时长；无 MP3 时使用表内时长作为演示进度。
- `锁屏通知`中电话和短信通过联系人 ID 使用联系人头像，其他通知使用对应 App 图标。
- `设置`目前只展示；用户名和 Wi-Fi 名称来自基础设置。
- `天气`的地点来自配置，天气与温度按当前显示日期和种子稳定生成。

## 微信配置

- `微信账号`必须且只能填写一行，作为玩家自己的昵称、微信号、头像和朋友圈封面；朋友圈封面路径留空时使用内置深色渐变。微信消息中的玩家 ID 固定填写 `SELF`。
- `微信联系人`与电话/短信的`联系人`完全独立，所有微信关联都使用微信联系人 ID。
- `微信群成员`逐行关联群聊和成员；群头像由成员头像自动拼合，每个群必须包含 `SELF`。
- `微信会话`决定聊天列表。联系人存在但没有配置会话时不会显示；单聊目标填写微信联系人 ID，群聊目标填写群聊 ID。“是否置顶”为“是”的会话排在最前并按最后一条消息时间倒序排列；非置顶且有消息的会话随后按最后消息时间倒序排列；没有消息的会话最后按本表行顺序排列。列表时间、摘要和未读数量都从“微信消息”自动计算，不在本表重复配置。最后消息发生在设备设定日期当天时，列表只显示 `HH:MM`；其他日期只显示 `MM-DD`。
- `微信消息`支持文字、图片、表情图片、定位，以及只用于展示的语音/视频通话记录。通话记录选择是否接通：已接通时必须填非负整数的通话时长（秒），未接通时留空时长，前端固定显示“已取消”。这两类记录不会发起真实语音或视频通话。`微信剧情`支持文字、图片、表情图片和由对方发送的定位消息。定位消息在“图片或表情路径”填写定位卡片图片，在“地图地点 ID”填写`地图地点`表中的地点 ID；点击卡片会打开对应地点详情、切换 SVG 并加入最近地点，返回一次恢复原微信会话。玩家发送文字时，“键盘按键序列”控制屏幕键盘的逐键高亮和模拟输入；emoji 直接写在文案中，不要写进按键序列，它会在对应文字输入完成后直接显示。图片、表情图片和定位卡片填写 `/media/...` 素材路径。聊天时间按会话分组，同一显示时间只在第一条消息上方显示一次；剧情消息使用发送时的本地时间并按分钟分组。
- 单聊、群聊的新消息都会更新微信角标并弹出顶部通知；玩家正停留在对应会话时不弹通知。
- `朋友圈`保存初始内容和可由剧情稍后显示的内容；发布人可以是微信联系人或玩家 `SELF`。初始朋友圈按序号从大到小显示，即最新内容在最前。“朋友圈图片路径”可填写 1～9 张图片，使用 `Alt + Enter` 换行分隔。多图最多按 3×3 排列，4 张为 2×2，点击图片进入黑底完整图片查看器。
- 玩家可随时点赞或取消赞；取消后再次点赞会排到点赞名单最后。`朋友圈评论`的回复对象填写被回复的评论 ID，不再填写联系人 ID；评论支持文字和最多一张小图，二者至少一项。
- `朋友圈发布剧情`配置玩家要输入的文字和逐张加入的图片；文字、图片都配置时必须全部完成后才能发表。没有激活发布剧情时相机仍可打开空白页，但发表按钮不可用；取消会丢弃草稿且不完成节点。
- `朋友圈玩家评论剧情`配置玩家主动评论或回复。没有匹配脚本时输入框和键盘仍可打开，但不能发送；配置文字和图片时必须两项都完成。
- `朋友圈互动剧情`按序执行显示朋友圈、联系人点赞/取消赞、评论和回复，并可选择生成朋友圈内部消息。消息显示在封面下方的“几条新消息”入口，不使用屏幕顶部通知。

微信剧情与短信剧情使用相同推进语义：对方消息按延迟自动到达，遇到 `SELF` 暂停，玩家按消息类型点击输入框、图片“+”或表情按钮准备内容，再点击发送后继续。键盘可随时开关，关闭时保留尚未发送的预设草稿；按键只提供视觉和音效反馈，不会自由录入配置外文字。剧情事件的“发生内容”选择对应的微信或朋友圈剧情类型，并填写相应剧情 ID。

## 短信剧情

同一个“短信剧情 ID”代表一整段剧情，一行代表界面中的一次发送或回复。“消息序号”决定先后，“发送方”可以在“我”和“对方”之间任意交替。

运行规则：

1. 剧情被激活后，连续的“对方”消息按各自行的延迟自动到达。
2. 遇到“我”时暂停。
3. 玩家打开对应聊天并点击输入框，页面才开始逐键输入预设内容。
4. 玩家必须自行点击发送；发送后继续处理后续消息。
5. 再遇到“我”就再次暂停；整段完成后才推进剧情事件。

“键盘按键序列”可空。留空时程序按消息文字生成逐字符输入序列；需要表现特殊按键过程时再填写自定义序列。

## 电话剧情和主动通话

`电话剧情`定义一段完整对白的 ID、联系人、方向和最后一句后的自动挂断等待；`电话剧情内容`按“一句一行”填写具体对白和出现延迟。同一联系人可以拥有任意多段对白。

`主动通话规则`保存每条规则的联系人、优先级、拨打次数范围和通话结果；每条规则必须使用唯一的规则 ID。`主动通话条件`按“一项条件一行”关联规则 ID，同一规则下的所有条件必须同时满足。不配条件行就表示该规则没有剧情限制。

- 条件类型为“剧情事件状态”时，条件值可选“未触发”“进行中”“已完成”。尚未激活的事件属于“未触发”；已激活并在等待计时、玩家操作或剧情结果的事件属于“进行中”；已经产生最终结果的事件属于“已完成”。
- 条件类型为“剧情事件结果”时，条件值可选“接听”“拒接”“未接”“完成”。
- 如果需要 OR 关系，配置多条结果相同、条件不同的规则；程序仍按规则序号选择第一条全部条件匹配的规则。

所有通话记录都可回拨，主动拨号按以下方式选择结果：

- 没有配置主动通话规则：默认对方不接。
- 每次使用同一对白：配置一条不限制事件和拨打次数的接听规则。
- 根据剧情切换：为规则在`主动通话条件`中填写一项或多项事件状态/结果条件。
- 有时接、有时不接：使用起始/结束拨打次数配置多条规则；不接听规则不填写对白 ID。
- 多条规则同时符合：使用规则序号最小的一条。

来电和主动拨打都会在对白最后一句显示完毕后，再等待“对白结束后挂断等待（秒）”并自动挂断。该等待用于保证玩家有时间读完最后一句。

## 剧情事件和分支

剧情没有单独的全局“线性/分支”设置。`剧情事件`定义触发方式与发生内容，`剧情分支`根据结果连接后续事件，因此一套剧情可以同时包含线性推进、不同结局和必须完成的卡点。

- 计时触发：事件激活后等待指定秒数。
- 操作触发：等待玩家打开 App、打开具体内容、进入短信输入框、拨打/接听/拒接电话等操作。
- “触发对象 ID”可对应联系人、照片、邮件、备忘录等目标。
- “仅衔接下一节点”不展示新内容，只完成本节点并连接下一事件。
- 剧情事件不再单独设置电量或关机动作。电量按基础设置中的时间间隔递减；关机由程序在所有实际进入的主线和支线完成后统一触发。
- 接听、拒接、未接等互斥分支只计算本次实际进入的路径，未进入的其他结果分支不会阻止关机。

`剧情分支`的“是否重试”为“否”时，重试结果单元格即使有内容也会被忽略；为“是”时至少填写一项。当前电话结果只允许“接听”“拒接”“未接”，多个结果必须在同一个单元格中用 `Alt + Enter` 换行，一行一个，不使用逗号、顿号或 `||`。

## 指定其他文件

默认命令读取兼容工作簿并写入前端数据目录。需要测试另一份工作簿或只导出到临时位置时可以使用：

```powershell
python convert.py --input .\outputs\another-config.xlsx --out-dir .\json-output
```

指定路径时仍建议先备份目标 JSON。准备发布的项目内容应回写默认位置，避免网页仍在读取旧文件。

## 修改工作簿结构时

新增工作表、字段或枚举选项时，至少检查以下位置：

1. 工作簿顶部填写说明、中文/英文字段名、示例、列宽、冻结、边框和数据验证。
2. `convert.py` 的表头别名、必需列、枚举映射、解析与跨表关联验证。
3. `content.json` 或 `story.json` 的目标结构，以及前端实际读取该结构的组件或 store。
4. 本 README、前端 README 和根 `AGENTS.md` 中涉及该行为的说明。
5. 在允许更新 JSON 时运行 `python convert.py`，再到前端目录运行 `npm run build`。

旧工作簿需要兼容时，优先在转换器中提供明确迁移或别名映射；不能兼容时，应让转换错误说明旧字段如何改写，而不是静默忽略数据。

## GitHub 备份注意事项

继续使用旧流程时，推荐把 `excel-json-tool/` 与 Vue 项目一起提交到外层 `PhoneSimulator` 仓库。兼容 `.xlsx` 文件会进入 Git 历史，便于回退；Cloudflare 只构建 `phone-simulator/`，不会把 Excel 发布到网页。

不要同时维护第二份手工复制的工作簿，否则容易出现版本不一致。Excel 打开时生成的 `~$*.xlsx` 临时文件已经在仓库根目录的 `.gitignore` 中排除。

如果你正在编辑工作簿但尚未转换，Excel 与 JSON 暂时不一致是正常现象。提交前是否运行转换取决于这次提交是“只备份表格草稿”还是“发布网页内容”；需要发布时必须转换并编译。

## 常见问题

- **提示文件被占用**：保存并完全关闭 Excel 后再运行转换。
- **密码正确但无法解锁**：确认转换成功，且网页使用的 `content.json` 已更新；重新构建或重启本地预览。
- **素材显示空白**：检查文件是否在 `public/media/`、路径是否以 `/media/` 开头、后缀是否真实可解码，以及大小写是否一致。
- **修改 Excel 后网页没变化**：先运行 `python convert.py`，再运行 `npm run build` 或重启开发服务。
- **脚本找不到前端目录**：确认 `excel-json-tool/` 和 `phone-simulator/` 仍然是同级目录。
