# PhoneSimulator 可视化配置编辑器

这是 PhoneSimulator 的独立可视化内容与剧情配置工具。它使用普通表单、消息序列和类似蓝图的剧情节点，帮助不熟悉代码或 JSON 的内容作者整理手机内容、剧情触发条件和结果分支。

> 可视化编辑器是新作品推荐使用的内容入口。它可以新建、打开和保存项目文件，也可以把旧版 Excel 一次性导入项目，并编辑普通内容、消息、对白、朋友圈脚本和剧情蓝图，最后导出手机网页使用的 `content.json` 与 `story.json`。旧版 Excel 转换流程继续保留作为兼容入口。

## 推荐工作流

1. 首次打开编辑器或点击“新建”时，会载入内置的空白作品模板：保留通用基础设置、桌面应用和微信玩家资料，不包含示例联系人、文案或剧情。已有 Excel 作品点击“导入 Excel”完成一次性迁移。
2. 把作品保存为 `.phone-project.json`，后续始终打开这个项目文件继续编辑。
3. 在问题列表中修正红色错误；黄色警告允许保留，但应确认符合剧情设计。
4. 点击“导出 JSON”，推荐选择仓库中的 `phone-simulator/src/data`，一次写入两份运行时文件。
5. 在 `phone-simulator/` 执行 `npm run build`，确认手机网页正式构建通过。

项目文件、运行时 JSON 和素材应一起备份。运行时 JSON 是导出产物，不要直接修改后再期待编辑器自动反向同步。

## 界面介绍

- 左侧“配置分类”：一级分类下带有二级目录，可直接进入桌面应用、相册、短信记录、微信会话、朋友圈或某一种剧情脚本，避免把不同结构的内容混在一个大表中。
- 中间编辑区：普通内容使用表格浏览，剧情流程使用节点和连线展示。
- 右侧“详细设置”：查看并填写当前内容或节点的完整参数。
- 底部“问题列表”：集中显示配置问题，并可定位到相关节点或内容。
- 中间视图右上角“查看 JSON”：只读查看当前项目编译后的 `content.json`、`story.json` 和编辑器元数据，不会直接修改 JSON。
- 顶部“导出 JSON”：检查当前配置后，分别下载两份运行时文件，或授权编辑器把它们直接写入手机项目数据文件夹。
- 顶部字段显示方式：可在“中文”“中英对照”和“JSON 字段”之间切换；该偏好只保存在当前浏览器中。

剧情蓝图中的端口由节点功能决定。流程端口表示事件先后和结果分支，数据端口用于联系人、会话、剧情段落或电话对白等引用；使用者不需要自行定义端口类型或数量。

剧情流程默认从左向右排列，分支节点会在纵向分开并继续向右延伸。画布左下角的“整理节点布局”按钮可以把手动移动过的节点重新按剧情关系排列。

## 编辑剧情蓝图

选择左侧“剧情流程”后，可以直接创建和连接剧情事件：

- 在画布空白处点击右键、双击或按 `Tab` 打开节点列表；也可以使用右上角“添加节点”按钮。
- 计时事件会在激活后等待指定时间，操作事件会等待玩家完成指定操作，电话事件提供接听、拒接和未接三个结果出口，结束节点没有后续出口。“关机事件”在激活并等待其触发延迟后关闭手机，也没有后续出口。
- 从节点右侧端口按住左键拖到另一个节点左侧的兼容端口即可连接。流程端口控制剧情先后，紫色虚线数据端口用于联系人、内容、短信/微信剧情、朋友圈脚本和电话对白等引用。
- 把连线拖到空白处时，只会列出与当前端口兼容的节点。选择后会在该位置创建节点并自动完成连接。
- 没有连接引用节点时，联系人或脚本等参数仍可直接在节点中选择；连接引用节点后，对应的内联字段会隐藏。删除数据连线后会保留最后一次引用值，作为可继续修改的默认值。
- 节点参数可以在节点内部或右侧“详细设置”中修改。勾选“初始激活”可以建立一条独立剧情入口；启用重试后可选择等待时间和需要重试的电话结果。
- 单击连线后按 `Delete` 可以删除连接。同一个流程出口只能连接一个后续节点，同一个数据输入只能连接一个引用来源；新连接会替换旧连接。

画布操作：

- 左键拖动画布空白处可以框选多个节点；按住 `Ctrl` 单击可以增减选择。拖动任一所选节点的标题时，全部所选节点一起移动。
- 鼠标中键拖动或按住 `Space` 再用左键拖动可以平移画布；滚轮以指针位置为中心缩放。
- `Ctrl+D` 创建所选节点副本，`Delete` 删除选择，`Ctrl+Z` / `Ctrl+Y` 撤销或重做蓝图修改。
- `F` 聚焦所选节点，`Home` 显示完整流程，`Esc` 取消当前连线或关闭节点列表。
- 参数较多的展开节点会在节点内部显示滚动区域；鼠标位于该区域时，滚轮滚动参数，移出节点后滚轮继续缩放画布。双击节点的非输入控件区域可以快速展开或收起参数。
- 节点和分组可以拖到当前坐标原点的上方或左侧，网格会跟随平移和缩放连续延伸，不存在可见的画布边缘。
- 右上角分组按钮可以创建剧情分组。拖动分组标题会连同完整位于框内的节点一起移动，双击标题可改名，右下角手柄可调整大小。
- “整理节点布局”会按剧情先后从左到右排列事件节点，并把已连接的引用节点放到对应事件附近。

节点位置、展开状态、引用节点、数据连线和分组只保存在可视化项目文件中；运行时 JSON 仍只包含手机剧情真正需要的事件、参数和结果分支。

## 编辑普通内容

左侧分类把非剧情配置分为“基础设置”“内容资源”“通信与日程”和“微信内容”。内容资源、通信、微信及消息脚本下面提供二级目录；选择目录后，中间区域只显示该类内容。目录选择保存在当前浏览器中，不写入共享项目文件。

- 基础设置直接选择对应项目，在右侧修改页面、设备、手机主人、壁纸、天气和桌面参数。
- 其他分类通过独立的“新建”下拉菜单选择允许创建的内容类型；搜索框旁的“全部类型”只负责筛选当前表格。
- 可以创建选中内容的副本、上移、下移或删除，也可以按住每行最左侧的排序手柄直接拖动。目标行上方或下方出现的蓝色横线表示最终插入位置。
- 新建内容会自动生成不重复的临时 ID；可以在右侧参数中改为作品使用的稳定 ID。
- 枚举和引用使用选项控件，数字、日期和时间使用对应输入类型；改变消息类型或收藏状态时，只显示当前需要填写的条件字段。
- 图片、音频和 SVG 路径使用 `/media/...` 格式。图片路径在当前部署能够访问素材时会显示预览，无法访问时仍可正常保存路径。
- 只要当前对象含有图片、音频或 SVG 路径，右侧“详细设置”底部就会显示“素材路径说明”。素材实际放在 `phone-simulator/public/media/`，编辑器只保存以 `/media/` 开头且带真实扩展名的相对路径，不会自动复制文件。
- 多项内容使用每行一项的编辑框，例如微信群成员和朋友圈图片。

短信初始记录、微信初始消息和朋友圈附属内容使用父子序列界面：

- “短信联系人与记录”先选择联系人，再编辑该联系人的初始短信；新增短信自动绑定当前联系人。
- “会话与聊天记录”先选择微信会话，再编辑该会话的初始消息；新增消息自动绑定当前会话。群聊发送人只提供当前群成员和玩家自己。
- “朋友圈”先选择一条朋友圈，再分别编辑其点赞和评论；新增点赞或评论自动绑定当前朋友圈，回复对象只显示同一条朋友圈中的评论。
- 子项默认收起为简短摘要，可逐条展开、创建副本、删除、上下移动或拖动排序。关联联系人、会话或朋友圈的内部字段不要求作者重复填写。

日历事件仍使用表格，但会按日期显示分组标题。其他相册、音乐、备忘录、邮件和地图等普通内容继续使用分类后的表格编辑。

表格行顺序就是编辑时唯一需要关心的顺序。普通数组按当前行顺序保存；地图地点、微信消息和朋友圈等运行时带有 `order` 的内容，会在移动后由编辑器自动更新该字段，不需要手动填写数字。拖动和上下移动只在同一种内容类型内部生效。

如果某种内容的顺序会影响手机中的显示或播放，右侧详细设置底部会出现该类型专用的“顺序说明”。基础设置或顺序没有实际作用的内容不会显示此提示。短信、微信消息、同一天的日程以及朋友圈点赞和评论只能在各自所属的联系人、会话、日期或朋友圈内部排序。

联系人、会话、地图地点、朋友圈等内容如果仍被其他配置引用，编辑器会阻止删除并列出引用位置。修改这些内容的稳定 ID 时，已有引用会自动同步更新；如果导入数据本身含有失效引用或重复 ID，底部问题列表会显示具体对象和字段。

## 编辑消息与对白

选择左侧“消息与对白”后，中间区域会切换为脚本列表和顺序编辑器。当前支持短信剧情、微信剧情、电话对白、朋友圈发布、玩家评论和联系人互动六类脚本。

- 在左侧脚本列表中搜索或按类型筛选；“新建”菜单只列出可创建的脚本类型。
- 脚本 ID、名称、所属联系人或微信会话、电话方向和挂断等待等整体参数在右侧“详细设置”中填写。
- 短信、微信消息、电话对白和朋友圈互动由上到下依次执行。可以添加、创建副本、删除、使用上下移动按钮，也可以按住条目标题左侧的手柄拖动排序；蓝色横线表示最终插入位置。
- 每个条目右侧可以收起或展开参数。收起后只保留发送方、类型和内容摘要，适合快速浏览与集中拖动排序；折叠状态会随项目文件保存。
- 朋友圈发布和玩家评论各自只有一份固定内容，不需要添加或排序条目。
- 发送方、消息类型或互动类型改变后，编辑器只显示当前需要填写的字段。联系人、会话、地图地点和互动人使用已有内容的选择列表。
- 条目缺少必填内容时，底部问题列表会显示脚本名称、条目序号和缺少的字段。

脚本名称只用于编辑器中辨认内容，不会显示在手机界面中。剧情蓝图引用的是稳定脚本 ID；被节点引用的脚本不能直接删除，修改脚本 ID 时已有引用会自动同步更新。

## 检查配置问题

底部问题列表会持续检查必填字段、重复 ID、失效引用、端口类型、一个端口上的重复连线、已失效连线和不可到达的剧情节点。红色问题需要修正，黄色问题表示配置可以保存但剧情可能不会按预期执行。单击问题会切换到对应分类，选中资源、脚本条目或剧情节点，并尽量把对应字段滚动到可见位置。

删除仍被使用的内容、脚本、生成的朋友圈或评论，以及有其他节点进入的剧情节点时，编辑器会列出引用位置并阻止删除。先到列出的位置改选其他引用或删除相应连线，再执行删除。

## 项目文件操作

编辑器使用单个 `作品名.phone-project.json` 文件保存作品内容和编辑器布局：

1. 点击“新建”并填写作品名称，可建立一个空白项目。
2. 修改字段、移动节点或展开/收起节点后，顶部作品名称旁会提示“有未保存修改”。
3. 第一次保存使用“保存”或“另存为”选择文件位置；之后点击“保存”可覆盖当前项目文件。
4. 点击“打开”可载入已有的 `.phone-project.json` 文件。打开其他项目或新建项目前，如果当前内容尚未保存，编辑器会先要求确认。

## 从旧版 Excel 导入

已有作品可以一次性迁移到可视化项目：

1. 点击顶部“导入 Excel”。
2. 确认替换当前项目后，选择 `phone-config-template.xlsx` 或由同一模板填写的 `.xlsx` 文件。
3. 导入完成后检查摘要和编辑器内容，再点击“保存项目文件”。
4. 后续继续打开保存得到的 `.phone-project.json`，不要同时修改 Excel 和项目文件。

导入会按旧转换工具的规则读取 36 张配置表，包括中文枚举、`LOCAL_TIME`、秒到毫秒转换、条件必填和跨表引用检查。发现工作表缺失、表头被修改、ID 重复或引用不存在时，编辑器会显示中文错误并停止替换。重新导入同一份或另一份 Excel 也会替换整个当前项目，不会与现有内容合并。

Chrome 和 Edge 可以在获得文件授权后直接保存到原文件。浏览器不支持文件授权接口时，“另存为”会改为下载项目文件，再次编辑时通过“打开”重新选择该文件。

编辑过程中，未保存内容会自动写入当前浏览器的恢复副本。如果页面意外关闭，下次打开编辑器时可以选择“恢复内容”或“放弃副本”。恢复副本只用于避免意外丢失，不能代替主动保存项目文件。

## 导出手机运行时 JSON

配置检查完成后，点击顶部“导出 JSON”生成手机网页读取的两份运行时文件。节点坐标、折叠状态、分组和脚本条目展开状态等编辑器信息不会进入这两份文件。

- 推荐使用“选择文件夹并写入”，选择仓库中的 `phone-simulator/src/data`。编辑器会写入或覆盖该目录下的 `content.json` 与 `story.json`。
- 浏览器不支持文件夹授权时，可以分别下载 `content.json` 和 `story.json`，再手动复制到 `phone-simulator/src/data`。
- 问题列表中存在红色错误时，导出会被阻止；黄色警告不会阻止导出，但应确认剧情流程符合预期。
- 导出运行时文件不等于保存可视化项目。完成内容编辑后仍要点击顶部“保存”，保留 `.phone-project.json` 项目文件。

运行时 JSON 更新后，在 `phone-simulator/` 中执行 `npm run build`，确认手机网页可以使用本次配置完成正式构建。

## 本地运行

需要 Node.js `20.19.0` 或更高的 20.x，或 `22.12.0` 及更高版本；建议使用较新的 Node.js 22。

首次运行时，在仓库根目录执行：

```powershell
Set-Location .\config-editor
npm install
npm run dev
```

终端会显示本地访问地址。查看结束后，在运行开发服务器的终端按 `Ctrl + C` 停止服务，避免继续占用端口。

检查静态生产构建时执行：

```powershell
Set-Location .\config-editor
npm run build
```

构建结果位于 `config-editor/dist/`。`dist/` 和 `node_modules/` 都不应提交到 Git 仓库。

## 与 Excel 和运行时 JSON 的关系

PhoneSimulator 网页最终读取：

- `phone-simulator/src/data/content.json`
- `phone-simulator/src/data/story.json`

可视化作品保存在独立的 `.phone-project.json` 项目文件中。项目文件还包含节点位置和折叠状态等编辑器布局信息，这些信息不会进入手机网页使用的运行时 JSON。

旧 Excel 工作簿和可视化项目是两个独立内容入口，不会自动双向同步；以后从 Excel 导入一次后，应继续使用可视化项目文件维护该作品。

编辑器内置的“新建项目”模板是独立快照，不会跟随兼容 Excel 或当前运行时 JSON 自动变化。以后如果确实要调整所有新项目的默认内容，应修改编辑器源码中的 `src/project/defaultTemplate.js`。

Excel 导入只在浏览器内读取所选文件并生成可视化项目，不会修改原工作簿，也不会自动覆盖现有运行时 JSON。只有使用顶部“导出 JSON”并明确下载文件或授权目标文件夹后，运行时文件才会生成或被覆盖。编辑器首次打开时显示的内容与点击“新建”完全相同，都是内置的通用空白作品模板；它不会读取或覆盖当前仓库中的运行时 JSON。
